# Complete Docker Learning & Reference Guide

Docker is an open-source platform that enables developers to build, package, ship, and run applications as lightweight, self-contained packages called **containers**. 

---

## 1. Containers vs. Virtual Machines (VMs)

| Feature | Docker Containers | Virtual Machines (VMs) |
| :--- | :--- | :--- |
| **OS Support** | Shares the Host OS kernel. Extremely lightweight. | Includes a full guest OS. Heavy resource usage. |
| **Size** | Megabytes (MB). | Gigabytes (GB). |
| **Startup Time** | Milliseconds / Seconds. | Minutes. |
| **Performance** | Native speed (almost no overhead). | Slower due to Hypervisor emulation. |

---

## 2. End-to-End Terminology

* **Docker Engine:** The client-server application installed on your host machine. It consists of the Docker Daemon (background service), API, and CLI client.
* **Dockerfile:** A text document containing a sequence of instructions (commands) used to build a Docker image.
* **Image:** A read-only blueprint (template) containing the application code, runtime, libraries, environment variables, and configurations. Think of it as a class in OOP.
* **Container:** A runnable, isolated instance of an Image. Think of it as an object instantiated from a class.
* **Registry:** A storage and distribution system for Docker images (e.g., Docker Hub, AWS ECR, GitHub Packages).
* **Volume:** A mechanism to persist data generated by and used by containers outside of the container's lifecycle.
* **Bind Mount:** Direct mapping of a folder/file from the host machine into the container. Great for local development.
* **Network:** An isolated virtual network that allows containers to communicate with each other or the external world safely.
* **Docker Compose:** A tool for defining and running multi-container Docker applications using a `docker-compose.yml` file.

## 3. Core Docker Commands Cheat Sheet

### Container Management
```bash
# Run a container from an image (downloads image if not local)
docker run -d -p 8080:80 --name my-web nginx

# -d : Detached mode (runs in background)
# -p : Port mapping (HostPort:ContainerPort)
# --name : Custom container name

# List running containers
docker ps

# List all containers (running and stopped)
docker ps -a

# Stop a running container
docker stop my-web

# Start a stopped container
docker start my-web

# Execute a command inside a running container (interactive bash terminal)
docker exec -it my-web bash

# View logs of a container
docker logs -f my-web

# Remove a container (must be stopped first)
docker rm my-web
```

### Image Management
```bash
# Pull an image from Docker Hub
docker pull node:18-alpine

# List local images
docker images

# Remove a local image
docker rmi node:18-alpine

# Build an image from a Dockerfile in the current directory
docker build -t my-app:1.0 .

# Tag an image for registry upload
docker tag my-app:1.0 username/my-app:1.0

# tag
docker tag practice-react yashpatoliyakevit/practice-react:latest

# Push an image to Docker Hub
docker push username/my-app:1.0
```

### System Cleanup
```bash
# Delete all stopped containers, unused networks, and dangling images/cache
docker system prune -a --volumes
```

## 4. Writing a Custom Dockerfile

A `Dockerfile` contains instructions executed in order. Each instruction creates a new layer in the image.

### Production Node.js / Express Example

```dockerfile
# 1. Base Image
FROM node:18-alpine

# 2. Set Working Directory inside the container
WORKDIR /usr/src/app

# 3. Copy package files first to leverage Docker layer caching
COPY package*.json ./

# 4. Install dependencies
RUN npm install --only=production

# 5. Copy the rest of the application code
COPY . .

# 6. Expose the port the app runs on (documentation only)
EXPOSE 3000

# 7. Default execution command when starting container
CMD ["node", "dist/main.js"]
```

### `.dockerignore` file
Create a `.dockerignore` in the same directory as the `Dockerfile` to prevent copying heavy or sensitive files:
```text
node_modules
npm-debug.log
Dockerfile
.git
.env
dist
```

> [!TIP]
> **Difference between `RUN` and `CMD`:**
> * `RUN` executes commands **during the build process** to create the image layers (e.g., installing packages).
> * `CMD` is the **default command executed at runtime** when the container boots up. There can only be one active `CMD` in a Dockerfile.

## 5. Data Persistence (Volumes & Bind Mounts)

By default, data created inside a container is **ephemeral** and will be lost when the container is deleted.

```
       [ Host Machine ]                      [ Container ]
   ┌──────────────────────┐              ┌───────────────────┐
   │ /var/lib/docker/     │              │                   │
   │  └── volumes/my-vol  ├─────────────►│  /usr/src/app/db  │  (Named Volume)
   │                      │              │                   │
   │ /home/user/project   ├─────────────►│  /usr/src/app     │  (Bind Mount)
   └──────────────────────┘              └───────────────────┘
```

### 1. Named Volumes (Production Recommended)
Managed by Docker on the host disk storage.
```bash
# Create a named volume
docker volume create pg-data

# Run container mounting the volume
docker run -d -v pg-data:/var/lib/postgresql/data postgres
```

### 2. Bind Mounts (Development Recommended)
Maps a host directory to a container directory. When you edit code on your computer, the container instantly reflects the changes.
```bash
# Mount current directory into the container
docker run -d -p 3000:3000 -v $(pwd):/usr/src/app -v /usr/src/app/node_modules node-app
```
*(Note: `-v /usr/src/app/node_modules` creates an anonymous volume inside the container to prevent the host's `node_modules` from overwriting the container's version).*

## 6. Multi-Container Orchestration (Docker Compose)

Docker Compose allows you to define complex multi-container apps (e.g., App + Database) in a single YAML file.

### Sample `docker-compose.yml`

```yaml
version: '3.8'

services:
  # Web application
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      - DATABASE_URL=mongodb://db:27017/myapp
    depends_on:
      - db
    volumes:
      - .:/usr/src/app
      - /usr/src/app/node_modules

  # MongoDB database
  db:
    image: mongo:5.0
    ports:
      - "27017:27017"
    volumes:
      - mongo-data:/data/db

volumes:
  mongo-data:
```

### Compose Commands
Run these commands in the directory containing `docker-compose.yml`:
```bash
# Start all services in the background (builds images if missing)
docker compose up -d

# Start and force rebuild of images
docker compose up -d --build

# View logs for all services in real-time
docker compose logs -f

# Check status of compose services
docker compose ps

# Stop and remove all containers, networks, and volumes defined in compose
docker compose down -v
```

## 7. Advanced Docker Best Practices

### Multi-Stage Builds (Optimize Image Size)
Split build-time dependencies (compilers, TS build step) from runtime dependencies to make production images as small as possible.

```dockerfile
# --- Stage 1: Build Phase ---
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# --- Stage 2: Production Phase ---
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install --only=production
# Copy only the compiled code from Stage 1
COPY --from=builder /app/dist ./dist

EXPOSE 3000
CMD ["node", "dist/main.js"]
```

### Do Not Run as Root
By default, Docker containers run commands as `root`. For security, switch to a non-root user (built into Node.js Alpine base images).
```dockerfile
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
# Use the built-in 'node' user
USER node
CMD ["node", "index.js"]
```
